у меня уже в find_segments.h есть вот такой класс описывающий множество отрезков (принадлежащих чему-то вроде отрезка):

struct SegmentPixels {
    std::vector<point2i> pixels;

    float median_magnitude = 0.0f;
    float median_abs_dev_magnitude = 0.0f;

    float median_angle_deg = 0.0f;         // in [0, 360)
    float median_abs_dev_angle_deg = 0.0f; // in degrees, [0, 180]
};

напиши simplify_segments.h simplify_segments.cpp simplify_segments_test.h (gtest юнит-тесты)
с функцией simplify_segment который получив на вход SegmentPixels выдаст в результат новый результат состоящий из вот таких новых классов отрезков
(напиши этот класс полностью в simplify_segments.h):
struct Segment {
    point2i a;
    point2i b;
}

при этом точки A и B находятся следующим образом:
1) у оригинального множества пикселей находится центроид (среднее значение координат)
2) проводится прямая через центроид перпендикулярная median_angle_deg (т.е. наше направление градиента отрезка задает перпендикуляр к отрезку, а значит и перпендикуляр к прямой этого отрезка)
3) за точку A берется пиксель с самой отрицательной проекцией на прямую (это один край отрезка)
4) за точку B берется пиксель с самой положительной проекцией на прямую (это другой край отрезка)

не забудь сделать функции для удобной и простой визуализации - на вход дана картинка и список Segment-ов, на выход получается картинка (в 2 раза более темная) с нарисованными поверх отрезками - каждый случайного цвета (из точки A в точку B)
